## Problem Statement

使用者是 agent，不是人。它打开这份技能后要在一次会话里做三件事：判断该不该用、走完 search→read、按规范合成。今天这三件事的入口，一个指向空路径，一个被细则埋住，一个散在六处。

三个可观测的坏结果：

**合成规范指向空路径。** SKILL.md 在八处引用 `docs/ANSWER-SPEC.md`，把这当成单一事实源。装机脚本只拷技能目录（`skills/kingdee-knowledge/skills/kingdee-knowledge`），`docs/` 不在拷贝范围。所以客户端 agent 照第一条指针走过去就是空的。本机实测 `~/.agents/skills/` 这个目录根本不存在——这份技能一次都没装上过，这个断链也就一直没被任何东西发现。

**该先做的被细则压住。** SKILL.md 537 行，三步流程占 92 行，拆词规范占 162 行。拆词细则不是每次都要读的：只有“清单召回不理想、要换词重搜”这一条分支才需要它，而它排在流程中间，任何一次全程加载都要先趟过它。

**同一个事实有六个出生地。** 契约数字在 README、SKILL.md、ANSWER-SPEC、GLOSSARY 各有一份抄本，productLineId 的中文标签在 README 与 ANSWER-SPEC 之间已经对不上。只有链接政策这一项补齐了“指向 contract.json”的指针，其余数字类事实零指针、零测试。

**维护者侧另有两个代价。** 改一个契约数字，得先读 contract.json 里 9280 字节、27 个 note/evidence 键的论证（占该文件 45%）。改一个文件名会静默打断守卫：`CONTEXT.md` 改名 `GLOSSARY.md` 之后，两条用例仍硬编码旧路径，现在是红的（离线组 67 通过 / 2 失败），而那个被改名保护起来的文件，眼下没有任何测试在读它。

## Solution

按**装载时机**分层，而不是按主题分类。这是 writing-for-agents 的核心判据：每次都走的进流程，只有部分分支才走到的推到指针后面。

三层，各有各的读者与配额：

**常驻层**是 AGENTS.md —— 一行指针，只在“要碰这个套件”时才被读到。它只写“去哪找”，不写“怎么用”。

**会话层**是 SKILL.md —— 每次回答金蝶问题都会全程加载，所以只留三步流程本身、指针、以及硬边界。拆词规范移出成 reference，因为它是分支材料：召回不理想时才读。

**按需层**是 skill 目录下的 reference 文件 —— 拆词细节、回答规范、链接可点性实测证据。它们随 `cp -r` 一起装机，所以指针落地，且不占每一次的加载额度。

同一批改动顺手收三件结构债：

**事实收成一个出生地。** 数字类事实（收词上限、产品线编号与标签、truncated 枚举、链接政策）全部只在 contract.json 声明，其余各处改成指针。守卫不再在用例里写字面量路径，改成从一份载体清单读——清单里一条写 GLOSSARY.md，改名只需改这一条。

**论证与数据分居。** contract.json 留数据（键集、编号表、政策、limits），“为什么这么定”与实测数字移进 ADR 或一份契约依据文档，原地留指针。判据是读者不同：代码会读的键与人会读的论证不该同处一个字典。

**版本变更史离开术语表。** GLOSSARY.md 前 52 行是 6.4→6.9 的版本段落，`## Language` 从第 53 行才开始。术语表只放术语，变更归 ADR。搬之前要先补一个空洞：6.9 删 `total` 这件事没有任何 ADR 记过，唯一出生地就是 GLOSSARY 里那一段。

删除类处置只碰一件事：docs 根 22 份 v4/v5 评测档（`eval-*`、`discovery-report`、`fullsnapshot-report`、`releasenotes-*`、`rg-eval-report-*`）。它们是 ADR-0011 已删除的那套本地评测与落盘体系的产物，今天 19 份零引用、1 份被 README 的 v4 历史小节提到。git 历史就是归档。

## User Stories

1. 作为客户端 agent，我要在第一次加载这份技能时先看到三步流程，这样我不必先读完拆词细则才知道该做什么。
2. 作为客户端 agent，我要照 SKILL.md 的指针去读合成规范时真的读到文件，这样我不必凭猜测合成。
3. 作为客户端 agent，我要在召回不理想时按一条明确的指针拿到换词细则，这样我不必自己发明拆词策略。
4. 作为客户端 agent，我要在遇到“链接看起来不对”时读到完整的重定向实测证据，这样我不会重现“只看首跳状态码”的误判。
5. 作为客户端 agent，我要在看到“必须给链接”时能一路追到代码真的读的那份声明，这样我判断的是现行政策而不是某份文档的记忆。
6. 作为客户端 agent，我要在查一个契约数字时只去一个地方，这样我不必在六份文档里比对哪份是对的。
7. 作为客户端 agent，我要看到产品线编号与其中文标签只在一处声明，这样我不会读到互相矛盾的标签。
8. 作为维护者，我要在改名一个文档后守卫仍能抓到真实漂移，这样改名的代价从“静默断掉保护”降到“改清单里一行”。
9. 作为维护者，我要改一个契约数字时不必先读三千字论证，这样我可以先改再看理由。
10. 作为维护者，我要在补一条新声明时知道论证该写去哪，这样 contract.json 不会继续变厚。
11. 作为维护者，我要能一眼看出哪些文档是同步点，这样我加一个新文档时知道要不要进清单。
12. 作为维护者，我要版本变更史与术语表分开，这样术语表被当作术语表读，不会被当成变更日志。
13. 作为维护者，我要在查“为什么删了某个字段”时找到一条 ADR，这样我不必去版本段落里考古。
14. 作为维护者，我要仓库里不再有已被架构废除的评测体系留下的档案，这样我判断“这套体系还在不在”时不会被文件名误导。
15. 作为维护者，我要删档之后 git 历史仍能取回原文，这样删除不等于销毁。
16. 作为维护者，我要票与规格进本地 git，这样“翻篇”这件事本身有版本、可回滚。
17. 作为维护者，我要装机产物里含 SKILL.md 引用的每一个文件，这样断链在装机时就暴露，而不是等客户端 agent 撞上。
18. 作为回归套件的读者，我要结构类断言集中在一处而不是散在八条用例里，这样我改文档时知道该跑哪几条。
19. 作为回归套件的读者，我要断言检查“指针目标存在”而不是“字符串出现过”，这样改名不会误红、死链才会红。
20. 作为接手这个仓库的人，我要第一次读 AGENTS.md 就知道去哪找票、去哪找术语、去哪找决策记录，这样我不必翻会话历史。

## Implementation Decisions

**分层判据用装载时机，不用主题。** 一个内容放哪一层，看它“是不是每次都要”。每次都走的进 SKILL.md 流程；只有部分分支才走到的进 reference。这条判据替代今天“按主题分节”的组织方式，是本次重排的主轴。

**技能目录是唯一装机单元。** 凡是 SKILL.md 指针指向的文件，必须落在技能目录内，与 SKILL.md 同级或在其子目录。装机脚本只拷这一个目录，任何落在 `docs/` 的指针都是断链。合成规范因此迁入技能目录；它在 reference 层，不占常驻额度。

**拆词规范移出流程，保留全部内容。** 它是召回效果的主要变量，删掉等于把质量交给运气；压成 60 行则丢掉实测脚注。所以是移动，不是压缩。SKILL.md 只在“清单召回不理想”这条分支上留一个指针。

**答案形态只留一处。** 今天 SKILL.md 里“三段式 / 原因分析 / 根因引用规则 / 来自社区经验 / otherSkipped”各出现 2–7 次，合成规范里还有一份完整版。收成：流程里一句“按合成规范写”加指针，形态细节只在 reference 里存在一次。

**守卫的载体路径从清单读。** 现在的两条同步断言各自在用例里写死文件名，所以改名会打断守卫。改成一份显式的“同步载体清单”，断言遍历清单。清单只有一条记录写着术语表文件名。

**结构类断言集中一处。** 今天散在多条用例里的“某文件必须提到某字符串”收进一组结构断言，判据写清是“指针目标存在 + 唯一真源被指向”，不是“字符串出现过”。

**契约数字的事实收口。** 数字类事实的权威位置是 contract.json 的声明键。文档侧只允许两类写法：直接指向声明，或标注“历史数字，现行值见声明”。产品线编号的中文标签以声明为准，README 与合成规范都改成指针。

**论证与数据分居，但论证不搬家太远。** contract.json 的 note/evidence 键移入 ADR 或一份契约依据文档，原地留一行指针。判据是“代码会不会读它”。⚠️ 这一条最不确定：那些 note 正在真实地阻止重复犯错，好几条记着“这里曾经判错过”。所以处置顺序是先建新址、再把指针放进原处，不做一次性剪切。

**版本史搬去 ADR，先补空洞。** GLOSSARY 的版本段落逐条落到 ADR。其中“6.9 删 total”没有任何 ADR 覆盖，需新建一条，因为它是破坏性变更，判据是“它没有任何可行动的用法”。搬完 GLOSSARY 的 `## Language` 从文件开头开始。

**删除只碰已废除体系的产物。** docs 根的 v4/v5 评测档删除。ADR、specs、tickets、research 一律不动：它们被 ADR 与代码按编号引用，删了就是断链。历史过程记录（`.scratch` 下的一次性计划与施工报告）不入库，也不删。

**票与规格进本地 git。** `.gitignore` 从整目录排除改为按目录白名单：`spec.md`、`map.md`、`issues/*.md` 入库，取证原料与历史计划不入库。判据沿用同机其他仓的既成约定——人写的文字进去，工具 dump 的字节出来。

**改名收口先做。** `CONTEXT.md` → `GLOSSARY.md` 已在暂存区，两条用例仍读旧路径。先把它们改成读清单，再动其他文档。顺序上这是止血，不排在后面。

## Testing Decisions

**好测试的判据。** 这次改的全是文档，而文档的“外部行为”是 agent 能不能找到并读懂。可验证的代理指标有四类，每类都只测外部可观察的后果，不测实现：

指针目标存在。SKILL.md 与 AGENTS.md 里每一条文件指针，目标文件必须真在盘上。这条最值钱：它是今天那个断链的直接反例，而且装机后也能跑——在装机产物里断言比在源码树里断言更接近真实使用。

装机完整性。跑完安装流程后，技能目录里必须含 SKILL.md 引用的每一个文件。这条把“断链”的发现时机从“客户端 agent 撞上”提前到“装机”。
**落地处（票 08，2026-11-17）**：折进既有的 `t_install_data_files`，不新增钉子 —— `HOME` 与 `--root` 指到临时目录真跑一次 `install.sh`，断言装机产物含 SKILL.md 引用的每一个同目录文件。两张反向确认：删掉源目录的 `CITATION-EVIDENCE.md` → 该断言红（73 通过 / 1 失败）；把装机改成只拷 `SKILL.md` → 红，指名缺 `ANSWER-SPEC.md` / `CITATION-EVIDENCE.md` / `WORD-SPLITTING.md`。

事实单一出生地。每个数字类事实（收词上限、产品线编号、truncated 枚举、链接政策）在文档侧的重述次数上限为声明的值，且每处重述要么是指针要么标了“历史”。这条替代今天“六份抄本各自为政、只有一项有指针”的状态。

守卫载体可改名。同步断言从清单读载体路径，清单里改名之后断言仍绿；把清单里某份载体的真实漂移造出来，断言才红。

**测哪些模块。** 无代码模块被改。被测对象是文档树与装机脚本，判据落在回归套件里新增的一组结构断言，以及既有的文档同步断言。

**先例。** 三条现成的：
- `t_link_policy_docs_in_sync` —— 六处载体 + 唯一真源 + stale 词表 + 废止标注豁免。它证明“多载体一致性”可测，也暴露了本次要修的缺陷（载体路径写死）。
- `t_docs_no_dead_mechanisms` —— 已删机制不得在文档里教人用，判据是段落级而非行级（变更说明常跨行）。它证明“文档不得教已删用法”可测。
- `t_answer_spec_diagnostics_wording` —— 诊断标记不得进答案正文。

**回归基线。** 改动前后都跑离线组。今天的基线是 67 通过 / 2 失败，两条失败同一成因（改名）。收口之后应全绿，且通过数不回退。联网组不因本次改动而变。

**变异验证。** 每条新增的指针断言与唯一真源断言，都要用“改坏再跑”验证一次：删掉指针目标 → 红；把某份文档的数字改成与声明不一致且不标历史 → 红；清单里改术语表文件名 → 仍绿。第三条是这次的关键——它证明改名不再打断守卫。
**补记（票 08，2026-11-17）**：第三条当时只对两条老同步钉子成立。本批新加的两条（`t_glossary_is_terms_only` / `t_numeric_facts_single_home`）仍把 `GLOSSARY.md` 写死在用例里，实测「`GLOSSARY.md` → `TERMS.md`、清单改一行、AGENTS.md 指针同批改」是 71 通过 / 2 失败。票 08 把这两处也改成经 `_sync_targets("glossary-document")` 取路径；现在同一变异 **73 通过 / 0 失败**，而把清单那一行改回旧路径 → 四条钉子同时红。

## Out of Scope

**代码模块深化。** 架构审查的七张候选里，观测口过宽（67 个再导出名、31 个零消费者）、并发离散加最小键重抛写了三遍、投影跑两遍、五个桩位 109 处手写改写——四条都是 in-process 的模块深化，另属一轮。本次只碰文档与仓库结构，代码一行不改。

**源码文本断言。** 11 条用例断言的是源码文本而非行为（`code_only` 剥离之后扫标识符），对改名会误红、对换个名字装回同一机制会全绿。那是测试面的改造，与文档结构不重叠，留到代码轮。

**题外但已记录。** 公开签名里 `sorts_type` 与 `rate` 两个参数没有对应 CLI 开关，而术语表写“不提供切档开关”。这是接口与文档的小矛盾，本次不单列票，改动到那几份文档时顺手对齐。

> **已处置（票 04，提交 3e224cd）**：`GLOSSARY.md:87-90` 改成两句 —— 对外契约确有这两个形参、**CLI 不给开关**；`sorts_type`/`rate` 与「不提供切档开关」的矛盾按「契约有形参、CLI 无开关」写明，不再称矛盾。

**不重构 `.scratch` 的历史。** 20 份一次性计划与施工报告留在原处。它们不入库，删了不可逆，而保留成本只是磁盘。

**不动 ADR / specs / tickets / research 的正文。** 它们被按编号引用。本次只允许在必要处（ADR-0004 那句 `issue #2`）删掉指向已删票的引用。

## Further Notes

**为什么这次不叫“文档重构”。** 按主题重组是原地打转：把 537 行分成更多更小的节，每次加载的量不变。这次动的是“什么在每次加载里”，所以判据只有装载时机一条。SKILL.md 的最终行数不必显著变小——拆出去的内容仍全部存在，只是不再每次都读。

**两个数字别写进验收。** 子代理初报“docs/research 2026-09 批 20 个文件”，实测是 18 个（另有一份 2026-11-04 未跟踪文件在目录里，不算那一批）。“docs 根 23 份里 22 份是评测档”——那 23 份里的第 23 个是 ANSWER-SPEC，它要迁走，迁走之后 docs 根只剩 `agents/`。验收写实测值，不写估算。

**六个桩位与三套取模块写法的关系要说清。** 这一轮不碰测试代码，但删档与改名会让一部分用例的路径常量失效。凡是本次改动触到的路径，用例必须同批改，不许留到代码轮——否则就是把红测试留给下一个人，等于这次重整的成果被抵消。

**`.scratch` 白名单的判据来源。** 它不是本仓新发明的规则。同机 `yolo-dataset-workbench` 的 `.gitignore` 注释写着“票面本身要入库，缓存在 .scratch/ 之外”，tracked 了 60 个 `.scratch` 下的文件；`strinova-rig` 与 `makcu-learning` 划的是同一句“判词与脚本入库，原料不入库”。本次沿用，不另立一套。

**后端的声明文件要一起改。** 切到本地 markdown 之后，`docs/agents/issue-tracker.md` 的标题行与 `docs/agents/workspace.yaml` 必须一致；deck 先读 workspace 文件，读不到才解析标题行，且只认 `markdown` 或 `local` 两个词。`triage-labels.md` 里还留着 GitHub 的 `gh label create` 语境，也要一并对齐到本地文件的做法。

## 进度
