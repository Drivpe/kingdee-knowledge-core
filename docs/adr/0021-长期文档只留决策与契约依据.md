# ADR-0021:内核仓长期文档只留决策与契约依据,显式推翻 structure-slim 的「不动档案」范围决定

日期:2026-11-20 | 状态:已采纳 | 关联:ADR-0011(去服务化与发行收敛)、spec kernel-only-three-repos(决策 5)、实施票 03

## 背景

structure-slim 这一轮把文档按 agent 的装载时机重排,当时的范围纪律是「不动档案」:
GLOSSARY.md、AGENTS.md、docs/research/、docs/specs/、docs/tickets/、docs/agents/
与旧 tracked .scratch 都留在 tracked tree,理由是它们承载了当时仍在用的判据与指针。

三仓拆分后,这些档案的读者变了。最终内核仓只承担搜索社区检索内核:对外是
`from kd.core import search, read` 与薄 CLI,运行的闭包只有 Python 标准库、src/kd
与包内 contract.json。研究、施工、票和 agent 治理材料对内核维护者不再是可执行的
入口,而是每轮都要重新判断「这条还在不在用」的负担。

## 决策

**显式推翻 structure-slim 的「不动档案」范围决定。** 删除以下 tracked 文件:

- GLOSSARY.md、AGENTS.md;
- docs/research/、docs/specs/、docs/tickets/、docs/agents/;
- 旧 tracked .scratch/structure-slim 与 .scratch/v2-ai-first-refactor。

保留 **docs/adr/** 与 **docs/contract-rationale.md**。contract.json 的 rationalePointer
继续指向 rationale,它和剩余文档里的活指针全部解析得到。

## 前置:现行判据逐项映射到保留载体

删除前逐项核过被删档案承载的判据。下表是可验证的映射:左列是被删档案里曾承载的判据,
右列是它现在的保留载体(节标题或 ADR 编号,不是「文件还在 git 里」这种空话)。

| 被删档案曾承载的判据 | 保留载体(现行正本) |
|---|---|
| 链接可点性的实测读数与两条禁令 | docs/contract-rationale.md 的 `linkPolicy.forbidden`、`linkPolicy.falseNegatives`、`linkPolicy.evidence.*` |
| 顶层 total 为何删除 | docs/contract-rationale.md 的 `search.note_totalRemoved` |
| other 档隐藏必须可见 | docs/contract-rationale.md 的 `search.note_otherSkipped` |
| 键集/字段集的单一来源与「声明必须有消费者」 | docs/contract-rationale.md 的 `note`、`read.note_consumer`、`limits.note` |
| 产品线编号的实测依据 | docs/contract-rationale.md 的 `productIds.evidence.*` |
| 拆词权移交调用层(原施工规格) | ADR-0016 |
| 6.7 行为修复的实测与验收记录 | ADR-0017(正文与补记 A–E 自带读数,不依赖原验收档) |
| 清单粒度改帖子级、版本变更史 | ADR-0014、ADR-0015 与各版本 ADR |
| 术语表/治理约定 | 无生产或测试消费者,按本 ADR 删除;原文从 git 历史取回,不登记为已迁移 |

内核源码注释里原指向施工规格/研究档案的两条指针已改指上表的保留小节或注明「历史走 git」。
删除的是施工与历史材料,不是未迁移的当前规则。原始取证档不另建归档副本,
从本仓 git 历史按被删路径取回(例如 `git show HEAD~1:docs/research/...`)。

## 测试与 README

- 删除文档同步载体表、术语表边界、数字重述额度、已删机制文档同步这四条专属钉子,
  以及只为它们存在的 helper。它们是治理档案的消费者,档案删掉后不再有可执行判据。
- 「文档里的文件指针必须解析到真实文件」与「契约论证指针解析得到」两条钉子收敛到
  保留文档;裸文件名仅在明确的历史叙述中保留,现行指引不得依赖已出仓文件。
- 公开 search/read 行为基线(41 场景)与离线回归保持不变,不依赖被删档案。
- README 缩成安装、import、CLI search/read、最小流程与测试说明,不再复制契约数字矩阵。

## 后果

- 内核仓的长期文档只剩「为什么这样决策」和「契约为什么这样定」两类。
- 历史取证的具体样本读数只能从 git 历史取回;这是有意接受的代价,用可验证的
  保留载体(ADR/rationale)换掉每轮都要重判「这条还在不在用」的维护成本。
- 技能与插件清单属应用层资产,接收仓与回退包见票 02;术语表与 agent 治理文档无内核消费者,按本 ADR 删除并从 git 历史取回,不虚构迁移回执。

## 布局边界

.scratch/kernel-only-three-repos/ 与 .scratch/kernel-only-three-repos-spec/ 是本轮规划工件,
只留本地,不进任何提交或推送;它们不属于最终内核仓的 tracked tree。
