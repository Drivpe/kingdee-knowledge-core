## 0. 结论先行

- **官方知识库没有一条文档写明「委外采购订单.要货日期」的取数来源。** 这是资料缺口，不是没搜到：
  委外工单、委外采购订单介绍、采购订单介绍三份字段表里，「要货日期」这个字段名**一次都没出现**
  （`委外采购订单介绍` 的物料明细字段表只列到发料明细，`采购订单介绍` 只列「交货日期」）。
- **「采购订单上存在要货日期字段」这条是官方背书的**，见多角贸易发版说明原文：
  「优化了多角贸易中订单的**要货日期和交货日期**的取值逻辑……以便更加准确的计算销售订单和采购订单的要货日期和交货日期。」
  即字段真实存在，但它的取数规则没有公开文档。
- **唯一一条指名「委外下推采购订单日期怎么算」的证据是社区采纳答案，且指的是交货日期、不是要货日期**：
  「采购订单的交货日期取委外订单上面的**计划开工日期 + 物料计划页签的提前期**。」
  这是社区经验，且问题标记的产品线是「采购管理」（企业版/标准版语境），不能直接当作旗舰版官方口径。
- **暂存也锁，与单据状态无关。** 锁定来自「产品委外采购订单」这个**单据类型**的锁定性配置
  （新增锁定 / 修改锁定），表单加载即施加，不看单据状态；另有界面规则 `IsDraw()` 一条独立来源，
  自动生成＝关联生成，`IsDraw()` 同样成立。所以「暂存」不构成解锁条件。

## 2. 取数来源：为什么文档答不上来

要货日期在委外采购订单上不是「单据头计算字段」，而是**转换规则的产物**。BOTP（单据转换规则）
的字段映射是配置数据，不是文档：同一张「委外工单 → 采购订单」规则，不同版本补丁、不同客户扩展后
映射可能不同。所以官方只能写「怎么查」，写不了「恒等于哪一列」。

可靠的现场判定动作（一步到底）：

```
开发服务云 → 单据转换管理 → 单据转换规则
→ 找「委外工单 → 采购订单」（目标单据类型：产品委外采购订单）
→ 扩展进入编辑态 → 目标单字段里找「要货日期」
→ 看它的「源单字段」或「计算公式」
```

- 源单字段写着「计划完工时间」→ 取的就是委外工单的计划完工时间。
- 源单字段写着「计划开工时间」→ 按社区口径，还要叠加物料提前期。
- **映射为空** → 走的是目标单字段默认值（多为单据日期或当前日期），这才是「改了也不生效」的真因。

## 3. 暂存态锁定的成因链

锁定在表单加载时施加，判定顺序（照 `802704654114213632` 的排查序）：

1. **单据类型锁定性**——「产品委外采购订单」预置了物料明细若干字段的新增锁定/修改锁定。
   「新增锁定」管的就是新建/生成出来的那一刻，因此暂存态必然命中。三份官方文档
   （订单日期、交货日期、备注）指向同一处，说明这是**产品预置行为**，不是客户配错。
2. **界面规则**——若规则前置条件为 `IsDraw()`，则凡关联生成（含委外工单审核自动生成）即锁定。
3. **字段本身锁定性**——基础资料属性字段默认锁定，需单独放开。

暂存态不参与任何一条的判定条件，所以「还没审核，应该能改」这个直觉在这里不成立。
