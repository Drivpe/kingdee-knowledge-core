# WORD-SPLITTING —— 拆词规范（**这是你的职责** —— 内核不再拆词）

**这是 `SKILL.md` 的 disclosed reference**（与它同目录、随技能一起装机）。
只有走到「清单召回不理想、要换词重搜」这一条分支时才需要读它——日常走 search → read → 合成
读 `SKILL.md` 即可；`SKILL.md` 的第 2 步在补搜判据里留一行指针指到这里。

⚠️ 拆词是**召回效果的主要变量**：ADR-0016 把生成权移交调用层之后，拆得好不好全在调用方，
内核不再有兜底。以下整节自 `SKILL.md` 搬入，**未压缩、未删实测脚注**；
只有两处形式调整：小节标题降一级（原文是 `###`，这里在 H1 下改成 `##`），
以及末尾「收词上限 N 路」那段留在 `SKILL.md` 的参数速查里（那个数字只许有一个出生地）。

⚠️ **v6.6 起内核不生成任何检索词**(ADR-0016):`--kw` 是唯一入口,内核把收到的词
**原样、按你给的顺序**发往上游。**怎么拆、怎么排,完全由你决定**——本节就是那份规范。
拆不好不再有"内核兜底",故请逐条对照。

拆词准不准,不看拆出的词多不多,看**有没有把问句里的稀有标识符单独拎出来一路**。上游是 **OR 语义**:
一路里空格拼接的多个词是"命中任一即召回",所以**拆得越细、词越常见,OR 展开的候选集越大 → 噪音越多**;
反过来,**稀有 token 是区分度的唯一来源**,它能把候选集从数千压到个位数。

## 四个维度(拆词时逐维过一遍)

1. **整句维度** —— 把**用户的原始问句或完整报错串原样**作为一路(标点、方括号、中英混写全保留),
   不要自己清理格式。它是跨**词汇鸿沟**的主力路:用户拿的是报错原文,官方文档标题却是产品术语,
   只有原句能凭语义近似召回;
2. **稀有标识符维度** —— 错误码 / 单号 / 数字型编码(`2510`、`27000`)、以及中英混写里的拉丁 token
   (`ENG_BOM`、`T_ENG_BOM`)。这类词的区分度最高,**单独成路**;
3. **症状词维度** —— 用户描述的现象词(`分母变平方`、`金额翻倍`、`多级展开`)。它们与官方文档的
   字段命名存在词法错位,**单独成路**可望命中"讲这个字段"的文档;
4. **字段/实体名词维度** —— 症状反推的领域术语(`生产单位数量`、`生产用料清单`、`BOM 正查`)。
   这是你比规则强的地方:你知道"分母变平方"背后是哪个字段。

## 一句排序原则

**路序就是召回顺序**(排序键第一维 = 你给的第几个词),所以:
**把"最能收窄候选集"的那一路排在最前 —— 而在中文语料里,这个位置属于纯数字标识符,不属于英文缩写。**

实测依据(2026-09-28 对照实验,金标 B = `873372977646105600`《BOM 分母平方案》,产品线 93;
**同一组词、同一个上游,唯一差别是路序**):

| 前置到第 1 路的词 | 上游 total | 金标 B 位次 |
|---|---|---|
| `2510`(纯数字错误码) | 2 | **1**(从第 4 升上来) |
| `生产单位数量`(实体词) | 4506 | 2(未变) |
| `分母变平方`(症状词) | 22038 | 2(未变) |
| **`BOM`**(拉丁缩写,**看起来最像标识符**) | 1308 | **12**(从第 2 掉下去!) |

(⚠️ 上表的 `total` 列记的是**当时**返回体的顶层 `total` —— **该字段自 v6.9 起已不再返回**
(见 `contract.json` 的 `search.note_totalRemoved`)。数字本身仍是当时的实测证据,故保留。)

即:**"这个词看起来稀有"不等于"它比同问句里的其他路更收窄"**——判断这件事需要语义,
而这个判断现在归你。上表是**唯一被实测背书的形态**:纯数字前置有效,拉丁缩写前置**有负结果**。

## 反例(不要把词拆得太散)

| # | 做法 | 后果(实测) |
|---|---|---|
| 反例 1 | 泛词各自成路 → `--kw 应用 --kw 禁用状态 --kw 网关` | 金标**掉出前 30**,候选集 11547 |
| 反例 2 | 把稀有 token 与中文词合并成一路 → `--kw "2510 应用为禁用状态"` | 金标**掉出前 30**,候选集 15180 |
| 反例 3 | 只给正对症状的那一路 → `--kw "应用为禁用状态"`(丢了 `[网关]`) | 金标**掉出前 30**(只差一个方括号) |
| 反例 4 | 把英文缩写放第 1 路 → `--kw "BOM" --kw "<整句>"` | 金标 B 从第 2 **掉到第 12** |

⚠️ 上表两处的 `total` 记的是**当时**返回体的顶层 `total`(上游候选集规模,会随语料漂移):
**该字段自 v6.9 起已不再返回**(它没有任何可行动的用法 —— 比对检索效果**只看金标位次**;
差额解释的载体现为 `otherSkipped`/`keywordsDropped`/`routeErrors`)。位次本身也有 ±1 的
固有抖动,不要把 ±1 当成"这次拆词变差了"。

## 整句必须作为一路发出(有实测依据,不要省掉它)

这一条的依据来自 ADR-0009 的实测,拆词移交后它**依然成立**(变的是"谁执行",不是"要不要做"):

| 做法 | 金标位次 |
|---|---|
| **原句单独一路** + 相关性排序(`sortsType=1`) | **第 1** |
| 片段融合(把拆出的词合并打分,MMLF 表 3) | **第 23** |

即:整句路携带的完整语境是片段路**无法替代**的——片段路拼不回"这句话在问什么"。
⚠️ 原句路曾由内核**恒常补入**(ADR-0009),该机制已于 v6.6 **整体废止**;
但"整句要作为一路发出去"这条**结论不变**,现在由你按本规范执行:拆词时**永远把整句作为其中一路**。

## 固定套路(照做即可)

报错码类问题(有错误码/单号):

```bash
kd search --kw "2510" --kw "应用为禁用状态[网关]" --product 93
#          ↑ 稀有标识符在第 1 路    ↑ 整句原样在第 2 路(标点全保留)
```

概念/配置类问题(无稀有标识符):

```bash
kd search --kw "<原句>" --kw "<症状词>" --kw "<字段/实体名词>" --product 93
#          ↑ 整句居首(此时它最收窄)
```
