# 金蝶知识库检索(kingdee-knowledge)——kd CLI 流程(单入口:search → read → 合成)

金蝶官方知识检索内核(`kd.core`,可 import 的库)的命令行入口 `kd`,
逆向自金蝶云社区公开后端,**纯匿名:零账号、零点数、无澄清、无对话限流**。
默认输出 JSON(stdout=数据,stderr=进度)。**库模式:无服务、无端口、无 HTTP、无本地落盘。**
v6 主轴是**彻底在线**(ADR-0005):用时在线搜、搜到即读即查;ADR-0011 去服务化后本地缓存与
发版说明库预囤**整体取消**,**不存在任何本地语料可供 rg**。

## 单入口定案(2026-09-18)

检索链路收敛成**一条**,没有第二条路可选:

1. `kd search` 出**清单**(标题 + 短摘要,不含正文);
2. 你按标题与问题的匹配度**自己挑**;
3. `kd read <id>` 取挑中那条的全文;
4. 你按 ANSWER-SPEC **自己合成**回答(默认**不开子代理**)。

三条定案(不得临场重开):

- **`ask` 已整体删除**——命令不存在(只会得到 argparse 退出码 2),不要尝试调用,也不要期待
  "一站式资料包"/`synthesisBrief`/`chunks` 这些随之删除的东西;
- **内核不做任何算法排分**:上游用的是**官方综合排序**,每一路拿回来的结果**本来就是排好序的**;
  内核唯一做的事是**删除重复内容**。内核里**没有 RRF、没有融合分、没有 rerank、没有 hitRoutes 计分**
  (这些是随 `ask` 删除的历史残留,不要在任何文档里复活它们);
- **合成权在你手里**(ADR-0008):套件零模型依赖,得到全文后由**你**按 ANSWER-SPEC 直接合成
  ——子代理看不到本对话、无法追问、交付常不完整(实测只回"已完成"不交正文),省下的上下文
  抵不过沟通成本。仅当单次要合成多份、或原文确实超长时才考虑开(见 ANSWER-SPEC 适用者)。

### 产品线默认(2026-09-27 重写:内核不再推导)

`search` 的 `product_id` **默认 93(星空旗舰版)**——常规提问不必显式带 `--product`。

- ⚠️ **内核不做任何字面推导**(决策 D14,2026-09-27):问句里出现「苍穹」**不再**被改写成 87。
  旧的别名表 + 裁决规则(`_derive_product_id`)已整体删除。你传什么就是什么;
- **值域两态**(v6.6,别混):**不传 / 传 `None` → 同义**,都取默认线 93;**显式 `0` → 不过滤**。
  故 `effectiveProductId` **不再出现 `null`**。⚠️ 旧版本是三态(`None` 表示不过滤),若你沿用了
  那个写法,**改传 `0`**(语义一致);要真正的不过滤必须**显式**传 `--product 0`;
- 实测代价(2026-09-17):同一问题不带默认时相关文档**零命中**,默认 93 后直接命中官方条目
  ——不带过滤的召回质量在中文语料上显著更差,默认值据此存在(留证在 `contract.json` 的 `productIds.evidence`)。

## 第一步永远是自举 PATH

**每个金蝶任务的第一步是这条自举命令。** 直接敲 `kd` 会得到 `command not found`,
而那**不等于**"机器上没装 kd"——是 PATH 没带过来:

```bash
export PATH="$HOME/.local/bin:$HOME/.kingdee-kit/bin:$PATH"; command -v kd && kd --version
```

- `~/.local/bin` 是 pipx 落点,`~/.kingdee-kit/bin` 是一键脚本落点;
- **agent 跑的是非交互 shell**,而 `install.sh` 把 PATH 写进 `~/.bashrc` / `~/.zshrc`
  —— 这两个文件**只在交互 shell 生效**,非交互 shell 根本不读它们,所以新机器上"装好了但
  agent 看不见"是常态,不是环境损坏;
- 上面这条命令自己把两个落点前置,**不依赖任何 rc 文件**,bash / zsh / sh 下均可用;
  回显版本号(如 `kd 6.9(library mode)`)即自举成功,**同 shell 内后续命令照常写 `kd`**。

Windows:Git Bash 用上面同一条;cmd / PowerShell 自举后走 `kd.cmd`。

### 自举失败才往下走

1. **绝对路径直调** —— 实测非交互 shell 下**不受 PATH 影响**,该通就通:
   - Linux/macOS:`~/.kingdee-kit/bin/kd --version`
   - Git Bash:`"$USERPROFILE/.kingdee-kit/bin/kd" --version`
   - cmd/PowerShell:`"%USERPROFILE%\.kingdee-kit\bin\kd.cmd" --version`
2. **仓库启动器**(两处都没有 = 机器上确实没装):`python3 <仓库>/src/kd_run.py search --kw "问题" --product 93`
   ——它自建 `sys.path` bootstrap,无需 PYTHONPATH,与装好的 `kd` 行为等价。仓库位置按序找:
   当前工作目录 → `kingdee-knowledge-kit` 的常见检出位置;找不到再问用户。
   **在此之前不要编造任何金蝶知识内容。**

想给这台机器装上第 1 级:见 README 的「安装」(pipx 一行,或 `install.sh` 一键)。
能力清单:`kd --help`(三条子命令与示例)与 `kd health`(内核版本/公开面/收词上限/限速档)

⚠️ **永远不要把 stderr 丢弃(禁 `2>/dev/null`)**:stdout=数据,stderr=进度与诊断;命令失败时先看
stderr/错误 JSON(带 hint),据此换调用方式,而不是静默改道 websearch。

## ⭐ 检索流程(三步,不要临场发挥)

### 第 1 步:kd search——常规问题一律此入口(出清单,你挑)

多路关键词检索,**只出清单(标题 + 短摘要)、不返回正文**。每个 `--kw` 一路,内核把它们
原样、按序各发一次上游检索(每路 10 条)→ **去重归并**(唯一的内核加工)→ 出**帖级**清单
(同一帖的多条回答合并为一条,条目 `id` 就是帖子号)。

```bash
kd search --kw "2510" --kw "应用为禁用状态[网关]" --product 93
# → {ok, keywords, queries[], routesPlanned, effectiveProductId, results:[…],
#    otherSkipped, routeErrors[], keywordsDropped, scanNote, contractCfgLoaded, stats}
# ⚠️ results[] 的字段集**按 type 分四份**(见下);url 按链接政策给值:三档都给链接
#    (question 用带回答号的长形式);`other` 档**恒不给链接**且**默认隐藏**;
# ⚠️ 顶层无 text(v6.6 删位置参数)、无 budget_exhausted(v6.6 删预算机制)、
#    无 page/pageSize/totalPages(v6.4 删清单分页)、无 total(v6.9 删)
```

**清单顺序就是上游相关度顺序**——这是本套件最重要的一条口径:

- 排序键只有 `(路序, 路内上游名次)`:先比"首次出现在第几路",同路再比"该路内名次"。
  **两者都不是内核算出来的**——路序**逐字等于你给词的顺序**,路内名次照抄上游返回顺序;
  ⚠️ **第 1 路是谁由你决定**(v6.6,ADR-0016):内核不再自己排路序,也不再有"稀有 token
  自动抢第 1 路"或"原句路恒常补入"。**你给的第一个 `--kw` 就是第 1 路**;
- **`hitRoutes`/`routes[]` 是纯信息字段,不参与排序**:它们只回答"这一条被哪几路撞到"。
  多路命中常意味着**泛文**(每个词都沾边的综述),只在某一路命中往往是**精确专文**;
  但这只是阅读提示,不是分数,内核绝不据此重排;
- `routesPlanned`:计划路数(去重前、受收词上限截断后)。它只有在**所有计划路都成功返回**时
  才可靠——若同时 `routeErrors[]` 非空,少的那几路可能是**失败**,别读成"词重复了"
  (原 `routesDegraded` 已于 2026-09-29 连键带提示删除:它报得自相矛盾,用户裁定「重复的就不要提示了」);
- **报错原文要原样作为一路**:用户拿上游报错码/症状描述来时,把原文整串原样作为一个 `--kw`
  (如 `应用为禁用状态[网关]`,连方括号一起)——它是跨**词汇鸿沟**召回官方文档的主力;
- **`routeErrors[]` 非空 = 部分路失败、召回不完整**:绝不要把"某路被上游拒绝"读成
  "官方没这类文档",此时应重试或告知用户;
- **`keywordsDropped > 0` = 你给的词有没发出去的**(超出 `limits.maxKeywords` 声明的上限),
  召回按定义不完整:先消化已获结果,判定置信度时把这一点算进去,别立刻重跑**或精简后重搜**。

**`results[]` 的字段集按 `type` 分四份**(ADR-0016 决策 6;第四份 `other` 为 v6.7 新增):

| 类型 | 字段集 |
|---|---|
| 公共(四档恒有) | `type`/`id`/`title`/`url`/`snippet`/`products`/`comments`/`hitRoutes`/`routes[]` |
| `question` 另加 | `adopted`/`answersCount`/`questionBody` |
| `article` 另加 | `supports` |
| `other` 另加 | `upstreamType`/`resourceType`(该档默认隐藏,需 `--include-other` 才返回) |

⚠️ **类型不适用的键直接不出现**(`article` **没有** `adopted`)——这与"值为 `null`"是两件事:
前者是结构性不适用,后者是上游这次没给值。按类型取字段,不要假设四档键集一样。

**参数速查**:`kd search --kw KW [--kw KW]... [--product N] [--global] [--include-other]`

- `--kw KW`:**必填**,可重复,每个词一路。**没有位置参数**——`kd search "整句"` 不再成立
  (它会报错,而不是把整句按字符拆开,见本步末「已删除的参数」)。**收词上限 7 路**(唯一声明:`src/kd/contract.json` 的
  `limits.maxKeywords`;实测 7 词 = 7 次请求 = 3.33 秒):超限时内核**按你给的顺序取前 7 个**,
  并在返回体里写明 `keywordsDropped`(丢了几条)。重复词自动去重且不通报;
- `--product N`:93=星空旗舰版(默认)、87=苍穹、1=星空企业版/标准版、2=星空侧二开问答专区、
  0=不过滤(显式指定才生效)——**内核不做字面推导**,你传什么就是什么。产品线怎么判见本步末「产品线判定」;
- `--global`:跨全部产品(不按 `--product` 过滤)。**产品过滤对每一路都生效**
  (不会因为用 `--kw` 就绕过 `--product`);
- `--include-other`:**返回「其他」档**(默认隐藏)。上游除三类已知实体外还会返回罕见类型
  (课程/学习路径/专题/直播),与前三档**不是同一种资料**(video/ppt 课件),默认不混进清单以
  免拖累挑选信噪比。⚠️ **隐藏时会写明跳过了多少条**(`otherSkipped` + `scanNote`),所以"没看到"
  永远能区分出是**开关关着**还是**上游没有**。该档 `type` 是 `other`,另带 `upstreamType`,
  且**不给网页链接**(实测无可点形式,见 `contract.json` 的 `linkPolicy`);
- 给空串 / 纯空白词会被内核显式拒绝(而**不是**静默产出空清单)——它宁可报错也不让你把
  "我没给词"误读成"官方没资料"。

⚠️ **已删除的参数**(v6.6,别再传,传了是 argparse 退出码 2):`--type`(类型筛选改由你按条目
`type` 自己筛)、`--max-routes`(只给一个 `--kw` 即为单路)、`--budget`(每路恒 1 次请求)、
`--chunk`(该能力未落地)。

#### 产品线判定(你的职责;内核不参与)

**产品线由你判定,内核只照用你显式传入的值。**(2026-09-27 起字面推导整体删除,见 ADR-0014)
判错等于拿完全不同的语料作答(实测同问句下 87 与 93 的 top10 **零交集**)。判据:

**① 问的是苍穹 → `--product 87`**:问句里出现「苍穹」「星瀚」,或问的是苍穹特有的概念
(BOTP、苍穹插件、苍穹开发助手、`LoginAfterBase`、微服务/容器化部署)。

**② 问的是开发/二开类问题 → 按"开发语境"再分一次**(开发类不是一条线,实测分成两处
**不同源的语料**,必须按语境选):

| 开发语境的信号 | 走哪条 |
|---|---|
| 苍穹侧开发:苍穹插件、Java 插件、`LoginAfterBase`、苍穹二开、开发助手 | `--product 87` |
| 星空/BOS 侧开发:BOS 设计器、账表开发、设计 BOM、`BOS开发`、星空二开 | `--product 2` |
| 开发类但**分不清哪一侧** | `--product 87`(87 是开发类的主语料;拿不准别猜第二条线) |

`--product 2`(星空侧二开问答专区)的**可执行判据是"返回条目类型恒为问答帖"**,不是候选集规模数值
(规模随语料漂移,且顶层 `total` 自 v6.9 起已不再返回;早期记的 611 是未带过滤时的口径)。类型构成的
实测留证在 `src/kd/contract.json` 的 `productIds.evidence`(10/10 与 9/9 全 question);当年的完整
候选集规模数字**只在仓库的历史施工档里**(维护者查,不随装机),**只作历史刻度、不作判据**。⚠️ 它是
**实测可用但文档长期未记录**的 ID,别因为没写就不用它。

**③ 意图模糊 / 与产品线无关 → 留空,用默认 93**:通用概念或判不出属于哪条线 → **不传
`--product`**;想跨全部产品线扫一遍 → `--global`(或显式 `--product 0`:`0` = 不过滤,
`--global` = 跨全部产品)。⚠️ 默认 93 **不等于**"用户指定了旗舰版",别写进答案。若问句确实指向
其他产品线,由**你**判定后显式传参,或先向用户确认;**切换产品线时在答案里说清楚**;

**④ 同一问题横跨两条线 → 分两次搜,不要合并**:`--product` 一次只接一个值,开发类问题若确实
横跨两侧就**分两次 `kd search`**(一次 87、一次 2)再合并判断,**不要**用 `--product 0` 图省事
把两条线混在一起。

**核对**:传了 `--product 87` 后看清单的 `effectiveProductId` 是否**等于你传的值**。内核不做任何推导,
它**必然相等**——**不等即 bug**,报出来而不是照用。没显式传参时默认 93,此时**不得**写"用户指定了旗舰版"。

> **历史事故记录(2026-09-06,规则已于 09-17 撤销)**:agent 回答「金蝶旗舰版 BOM 维护」时,中途把
> `--product 93` 变道为 `--product 0`,召回星空企业版内容(ENG_BOM/T_ENG_BOM)且未甄别,把企业版
> 答案当成旗舰版输出(正确答案:pdm_mftbom)。事故后曾立三条硬规则(禁不带 --product、禁变道 0、
> 禁切其他产品线),**2026-09-17 全部撤销**:默认已改为 93,"不带 --product"不再等于不过滤,第一条
> 失去对象;后两条被判定可由默认值自然规避。事故事实保留供追溯,现行做法就是上面四条判据。

### 第 2 步:kd read——从清单挑出 id 再取全文

清单只给标题与短摘要,**要全文必须显式读**——这一步由你决定读哪几篇,内核不再替你挑:

```bash
kd read <id>                          # type=knowledge → 官方文档全文
kd read <id> --kind question          # type=question → 问题+全部回答+追问链(传帖子号)
kd read <id> --kind article           # type=article → 社区文章全文
# --kind 照抄清单里的 type 字段,零翻译
```

⚠️ **无需翻译**:清单条目的 `id` 就是**帖子号**,`kd read <id> --kind question` 直接用
(2026-09-27 起 `questionId` 已删除,双 id 空间不存在)。

⚠️ **问答帖的 `truncated` 是原因枚举**(v6.6,ADR-0016 决策 7)——两种成因**行动相反**:

| 值 | 含义 | 你该做什么 |
|---|---|---|
| `"answer_limit"` | 帖子太长没读完(翻页上限 / 详情只展开前 N 条) | 接受现状,在答案里用正常语言说明"该帖还有未展开的回复" |
| `"upstream_error"` | **上游报错** | **重试**(或换词),不要当作"这帖只有这些答案" |
| (键不存在) | 读完了 | 正常 |

⚠️ 这是**给你看的诊断**,不得写进给用户的答案正文(见 ANSWER-SPEC 反例节);没有该字段时
不得假设"内容完整"以外的结论,`"upstream_error"` 时**必须**重试或声明不完整。

**挑选判据(2026-09-28 增补;这是纪律,不是内核行为)**

内核**不替你挑**(ADR-0008/ADR-0013:清单是唯一交付物,挑选权在调用方)。判据只存在于本节,
**没有任何代码在执行它**——它的约束对象是**你**。按下列顺序读,别按直觉:

1. **先读清单前 3 条,不要跳读**。清单顺序就是上游相关度顺序,**跳过前面的去读第 8 条是无依据
   的**。实测:金标文档常在 `hitRoutes=2` 的泛文之后、以 `hitRoutes=1` 出现——**这不代表它更差**,
   只代表它被更少的路撞到;
2. **读够就停**:先读 2–3 条,不够再回头读第 4、5 条。**不要一次把清单读光**
   (每次都真实消耗上游,且长全文会挤占你的上下文);
3. **`type` 决定它能证明什么**(根因引用规则,见 ANSWER-SPEC 第 7 条):`knowledge`(官方文档)
   **可以**支撑「问题原因分析」的机制/字段/流程结论;`question`(社区问答)与 `article`(社区文章)
   **只能**用于症状对齐("我遇到的和你一样"),**不足以**当根因。要答"为什么"而清单里只有
   `question`,**必须再搜一次**去拿 knowledge,不得用问答帖的推测充当根因;
4. **标签不是判据,`snippet` 也不能当结论**:`snippet` 只是上游短摘要,
   **具体步骤/菜单路径/字段名必须 read 全文核对**;正文 `products` 是中文类目名,值域与产品线 ID 不可比;
5. **要不要补搜,看清单的客观信号而不是"感觉不够"**:`routeErrors[]` 非空 ⇒ 部分路失败,
   **召回不完整**,应换词重试而不是就此作答;`keywordsDropped > 0` ⇒ 你的词有没发出去的;
   `otherSkipped > 0` ⇒ 有罕见类型条目被默认隐藏(⚠️ 不得读成"没有这类资料",需要时加
   `--include-other` 重搜);全清单**没有任何标题**贴近问句 ⇒ 很可能真的没查到(**不是**"官方
   没有"),换词再搜一轮;
6. **一次读不到就换词,别改产品线**:检索不顺手时先换检索词——**拆词规范在
   `WORD-SPLITTING.md`**(同目录、随技能装机):清单全是泛词命中、没有精确命中时读它换词重搜。
   **不要因为检索不顺手就把 `--product` 切来切去**——那是串线事故的形态。

### 第 3 步:合成(你的职责,不是 kd 的)

**kd 不合成回答**(ADR-0008,零模型依赖)。拿到全文后**由你直接合成**——**默认不开子代理**
(2026-09-17 定案,理由见「单入口定案」第 3 条)。

**按同目录的 `ANSWER-SPEC.md` 写**(合成格式的单一事实源,随技能一起装机)。三段式结构、
引用规则、根因引用规则、置信度三档与反例清单都在那里,**本节不复述**——它们是形态细节,
只在 ANSWER-SPEC 里存在一次。只有三件事在这一步提醒你,因为它们是**流程侧**的:

- **开头直接给定性结论**:不要元信息、不要 JSON、不要"置信度头"、不要内部编号("源6"),
  结尾不加审计披露/复盘段;
- **引用照抄**清单/全文里的原始 `url` 字段,不自己拼路径;`url` 为 `null` 时只给标题与出处。
  链接政策按 kind 分档、唯一真源是 `src/kd/contract.json` 的 `linkPolicy`(见 ANSWER-SPEC 第 3 条),
  实测证据(重定向判定规则、三档数字、反例)在同目录的 `CITATION-EVIDENCE.md`;
- **资料不足时反问一句关键澄清**(见下「置信度」),而不是堆一段缺口声明。

**置信度(内部判断,不输出)**:全文有段落直接说明机制/字段/步骤 → 正常作答;有材料但没覆盖用户问的
那一点 → 点明「现有资料未覆盖 X」并**反问一句关键澄清**;清单与问题不匹配 → 直说没查到、**给确认渠道**,
**绝不编造菜单路径/字段名**。依据只用清单的客观信号(`routeErrors`/`keywordsDropped`/`otherSkipped`/
`truncated`),以及"单条 `hitRoutes` 高但内容泛 ⇒ 别当权威依据,精确专文常在精确路命中";**这些标记
不得写进答案正文**,不写分数也不写"置信度"字样(三档语义与反例见 ANSWER-SPEC 第 5 条)。

## 站外兜底(清单空手或解释不了根因时)

`kd search` 的清单空手、或读到的全文解释不了根因时,才动用 websearch:

```bash
# 站外兜底,回答必须标注「站外语源」
site:vip.kingdee.com 发版说明 <修复项关键词>

```

诚实边界:部分发版说明不在搜索索引内,搜不到≠不存在;不要因为这一跳也无果就断言「官方没有」,
按 ANSWER-SPEC 写「现有资料未覆盖」。
