# CITATION-EVIDENCE —— 链接可点性的实测证据

**这是 `ANSWER-SPEC.md` 的 disclosed reference**(与它同目录、随技能一起装机)。
只有走到「这条链接看起来不对、到底该不该给」这一条分支时才需要读它;日常合成读 ANSWER-SPEC 即可。
ANSWER-SPEC 第 3 条只留结论,「为什么这么判」与实测数字全在这里。

## 判定可点性:必须跟随重定向看最终 URL

判据是 `url_effective`,**不得只看首跳状态码**。**两个方向的误判都实际发生过。**

### 匿名复测(2026-09-29):三档都可点

| kind | 复测数字 | 说明 |
|---|---|---|
| `knowledge/` | **14/14 可点** | 含 09-27 文档误记为「稳定 302」的 `873372977646105600`(实测 200) |
| `article/` | **12/12 可点** | 含被**迁移**成知识文档的那条(见下) |
| `question/` | **22/22 可点** | 只限带回答号的长形式;死的是 URL **形式**,不是这一档 |

### 三个反例(都是「只看首跳会翻车」的实例)

- **成功重定向到 404 页**:`question/` 的**最终状态码恰为 200**,只看状态码会把**失效**链接
  判成可点。这一条同时解释了为什么 09-28 把 `question` 整档判死:**当时**测的是单数短形式,
  它确实恒死;而**改判后的长形式**才是活的。
- **同型第五例(2026-09-29 复验)**:`/school/detail/<id>` 也因这一条被误记为「200 可点」,
  实为恒死。
- **被迁移成知识文档的那条**:`article/248777993676668672` 首跳 **302**,但最终 URL 是
  `/knowledge/248777993710223104` 且该页**可点**——只看首跳状态码会把**可点**链接判成失效
  (09-18 与 09-27 两份文档都这么记错过)。

## 登录态假阴性:为什么不做逐条预判

匿名侧判定会对**登录态用户产生假阴性**——用户登录态实测 6 条中,有 2 条匿名侧为 302 而登录侧
可点。⚠️ 该样本仅 6 条,**不足以断言「登录态下全部可点」**,故 ANSWER-SPEC 只声明「给链接」,
不声明「保证可点」。若将来出现用户报告某个 `knowledge` 链接打不开的实例,须重新评估。
